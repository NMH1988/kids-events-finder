- **Decisions & gotchas:**
  - The terms were read on 2026-11-24 from the providers' public pages; what was not read (FOSSGIS usage terms, Ticketmaster's branding guide and FAQ, OpenRouter's provider terms list, GitHub's terms, bahn.de's terms, the Qwen providers' terms, most of Transitous' sources page) is listed as an open question in its entry.

  - The key-status check of 2026-11-24 ran as small Python scripts that read the key through `config.get_api_key()` and put it only in the request header; the key was never on a command line, in shell history or in any output.
  - Rule 2 was first written as "only in the authorisation header"; the Ticketmaster Discovery API takes its key as the `apikey` query parameter, so the rule now says "in the way the provider's API requires" and forbids logging or showing the URL or request errors, which is the owner's intent (no exposure in any form).
