### T5.7 Hidden characters in model output and the knowledge base caption (M) · status: todo · issue #30
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): user interface and interaction quality, function calling (the human-in-the-loop step and the answer details); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.3 (transparency: the caption says what goes where, as the privacy policy will), 2.11 (the memory save in the answer details: shown as saved only when it was), 4.3 (what the app shows comes from the tools, with no hidden text).
**Depends on:** T5.2 (uses its `visible_text` and `shown_json`)
**Acceptance criteria** (drafted by Claude, approved by the owner on 2026-11-27)
- [ ] The `search_knowledge_base` caption says the search text goes to the AI model service to find matches and that nothing goes to map, event, weather, geocoding or train services, instead of "Nothing leaves the app" - verified by an `AppTest` that finds the new caption.
- [ ] A lone surrogate never reaches the stored history: one shared helper replaces it with U+FFFD in every AI message the graph stores (the answer text, `tool_calls`, `invalid_tool_calls` and the raw copy in `additional_kwargs`, with their names, ids and arguments), in the agent node before the approval pause and in `human_review`'s edit branch (a parent's JSON edit can hold the escape `\ud800`); ids that only differed by a surrogate stay different after the replacement; `src/tools/registry.py` uses the same helper, so a service's text gets U+FFFD instead of today's "?" - verified by graph tests with a scripted model in `tests/test_agent.py` that check the stored message holds no lone surrogate and the messages the model receives next encode as UTF-8: a surrogate in a tool call (the pause payload `pending_tool_calls` already holds the replaced value), in an answer followed by a second question, in a parent's edit, and two ids that differ only by a surrogate; and the service-text test in `tests/test_tools_and_feedback.py`, changed from "?" to U+FFFD.
- [ ] "How this answer was made" shows tool names and arguments with hidden characters (bidi, zero-width, surrogates) escaped, like the approval panel (`visible_text`, `shown_json`), and shows a memory save through `memory_save_args` (only the topic and the feeling, never other keys the model wrote) - verified by an `AppTest` of the answer details with a tool call holding hidden characters and a memory save with an extra key.
- [ ] "How this answer was made" marks a call that did not run: a call the parent rejected, or a memory save refused because memory was off, shows "not run" (a memory save: "not saved") next to it, so no listed call reads as done when it was not - verified by an `AppTest` of the answer details with a rejected search, a rejected memory save and a memory save refused with memory off.
- [ ] The approval panel's widget keys use a hash of the call id, so a call id with any character never breaks the panel, and the keys still change with the pause - verified by an `AppTest` with such a call id and `test_approval_widgets_are_keyed_by_the_pause`, adapted.
- [ ] The system prompt is unchanged - verified by the PR's diff (no change under `src/prompts/`).
