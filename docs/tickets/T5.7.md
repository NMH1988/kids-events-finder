### T5.7 Hidden characters in model output and the knowledge base caption (M) · status: done · issue #30
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): user interface and interaction quality, function calling (the human-in-the-loop step and the answer details); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.3 (transparency: the caption says what goes where, as the privacy policy will), 2.11 (the memory save in the answer details: shown as saved only when it was), 4.3 (what the app shows comes from the tools, with no hidden text), 6.3 (source credits only for calls that ran).
**Depends on:** T5.2 (uses its `visible_text` and `shown_json`)
**Acceptance criteria** (drafted by Claude, approved by the owner on 2026-11-27)
- [x] The `search_knowledge_base` caption says the search text goes to the AI model service to find matches and that nothing goes to map, event, weather, geocoding or train services, instead of "Nothing leaves the app" - verified by an `AppTest` that finds the new caption and a text search of `README.md` that finds no "stays inside the app" for the knowledge base search.
- [x] A lone surrogate never reaches a model request or the stored history: one shared helper replaces it with U+FFFD in every AI message the agent node returns (the answer text, every string in `additional_kwargs`, and the names, ids and arguments in `tool_calls` and `invalid_tool_calls`), before the approval pause, and in the parent's whole decision (edited arguments and a reject reason) before `resume_turn` hands it to the graph (a JSON edit can hold the escape `\ud800`); distinct ids stay distinct and equal ids stay equal after the replacement; `src/tools/registry.py` uses the same helper, so a service's text gets U+FFFD instead of today's "?" (today the checkpointer also turns a lone surrogate into "?" when it saves, but the message still in memory holds it, so the model's next request in the same turn fails) - verified by graph tests with a scripted model in `tests/test_agent.py` that check every request the model receives encodes as UTF-8 and the stored message holds U+FFFD: a surrogate in a tool call that runs without a pause (the model's next request in the same turn), in one that pauses (the pause payload `pending_tool_calls` holds U+FFFD), in an answer, in a parent's edit, in a reject reason, and ids (two that differ only by a surrogate, and one with a surrogate next to one holding a real U+FFFD at the same place, stay distinct; two tool calls with the same id keep it shared, so the approval panel still offers only Reject for repeated ids); and the service-text test in `tests/test_tools_and_feedback.py`, changed from "?" to U+FFFD.
- [x] "How this answer was made" shows tool names and arguments with hidden characters (bidi, zero-width, surrogates) escaped, like the approval panel (`visible_text`, `shown_json`), and shows a memory save through `memory_save_args` (only the topic and the feeling, never other keys the model wrote) - verified by an `AppTest` of the answer details with a tool call holding hidden characters and a memory save with an extra key.
- [x] Only calls that ran count as run: `src/agent/runner.py` marks each call in the turn's result as run or not (a call the parent rejected did not run, known from a fixed marker that `human_review` sets on the rejection's ToolMessage, such as its `artifact`, never from its text; a memory save counts as saved only when its result holds a `saved` entry, the test `remembered()` uses, so a save refused because memory was off or by any of the tool's other checks is "not saved"); "How this answer was made" shows "not run" (a memory save: "not saved") next to such a call, and the source credits under the answer and the feedback's `tools_used` take only calls that ran (a memory save the tool refused did run: it stays in `tools_used` and shows "not saved") - verified by a runner test with a scripted model (a rejected search, a memory save refused with memory on and one refused with memory off come out marked, an approved save comes out saved) and an `AppTest` of the answer details and the credits (a rejected `find_nearby_places` adds no OpenStreetMap credit), and an `AppTest` that rates an answer with a rejected call and checks the `tools_used` passed to `save_feedback`.
- [x] The approval panel's widget keys use a hash of the call id, so a call id with any character never breaks the panel, and the keys still change with the pause - verified by an `AppTest` with such a call id and `test_approval_widgets_are_keyed_by_the_pause`, adapted.
- [x] The system prompt is unchanged - verified by the PR's diff (no change under `src/prompts/`).
