### T5.2 Parent-friendly approval form instead of raw JSON (M) · status: todo · issue #21
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): interactive prototype, user interface and interaction quality, function calling (the human-in-the-loop step); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.6 (personal details in free text, place-name fields), 2.9 (limits enforced on the server), 4.2 (no dark patterns).
**Depends on:** T5.1 (both change `_render_approval` and its `_run` call in `views/chat.py`)
**Acceptance criteria** (drafted by Claude, approved by the owner on 2026-11-24)
- [ ] For `find_nearby_places`, `search_family_events`, `get_weather_forecast` and `find_train_connection` the approval panel shows one labelled field per argument (town fields, a country choice, a place category choice with readable names, date pickers, a time picker), filled with the model's values, instead of the JSON text area - verified by an `AppTest` in `tests/test_app.py`.
- [ ] "Run with my edits" sends the field values; choices come only from the tool schema (country, category), dates stay within the tool's limits (end not before start, no further ahead than the tool allows), and a value the tool would reject shows an error and disables the button - verified by unit tests of the form-to-arguments function and an `AppTest`.
- [ ] Town fields still pass `decision_problem` and the `PlaceName` check: a name, an exact age, a health word or a sentence typed into a town field is blocked before anything is sent - verified by tests in `tests/test_app.py` and `tests/test_agent.py`.
- [ ] A tool the form does not know falls back to today's JSON editor inside an "Advanced" expander, with today's checks - verified by a test.
- [ ] Approve, "Run with my edits" and Reject keep today's meaning, the budget table is unchanged, and the server-side length limits (`MAX_DECISION_CHARS`, `MAX_EDIT_VALUE_CHARS`, `MAX_REJECT_REASON_CHARS`) still apply - verified by the existing tests, passing without changes.
**Notes:** files: `views/chat.py` (the form), a small pure function for form values to arguments (in `views/` or `src/`, tested without Streamlit), limits from `src/config.py`. No new data leaves the app: the same arguments, entered in a friendlier way. Keep the three buttons' look as today (no new nudge towards Approve, 4.2).
