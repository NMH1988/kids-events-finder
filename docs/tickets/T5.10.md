**Acceptance criteria** (drafted by Claude, to be approved by the owner)
- [ ] A second retrieval question set (at least 20 made-up questions in English, German and Vietnamese, with their expected places) in which every question has more than `config.RETRIEVAL_TOP_K` candidates after the city, age and indoor filters, and some have a near-miss distractor (a candidate that passes the filters but is not in `relevant`) - verified by a test that counts each question's candidates offline with `candidates()`.
- [ ] Every question in the new set passes `check_input`, like the current set - verified by extending the privacy-check test that reads the evaluation questions to the new file.
- [ ] Where a city has too few places, new knowledge base entries are added in the project's own words with their official website, with no medical or therapy places and no accessibility claims; if the owner chooses a `checked_on` date per entry (open question), `Place` gets that field and the schema test requires it - verified by `tests/test_knowledge.py` and the owner's review of the new entries (as in O3).
- [ ] `scripts/evaluate_retrieval.py` takes the question set as an option, and the default run is unchanged - verified by a unit test.
- [ ] After the owner's go-ahead: `python -m scripts.check_links` on the new entries, the index rebuilt, and one run of all five variants on the new set, recorded in `docs/EVALUATION.md` with a result paragraph that says which steps help - verified by the printed outputs, quoted in the progress entry.
