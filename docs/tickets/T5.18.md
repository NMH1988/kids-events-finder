### T5.18 Every model step keeps its own message id (S) · status: todo · issue #51
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): multi-step reasoning, function calling; Legal (`docs/LEGAL_COMPLIANCE.md`): 4.3 (the history keeps what the tools returned), 6.3 (no lost source credit for a step that ran).
**Depends on:** T5.7
**Acceptance criteria** (drafted by Claude, approved by the owner on 2026-11-28)
- [ ] Every AI message the agent node stores has an id that no other message in the thread has: when the model's message comes with an id already used in the thread, the app gives it a fresh id of its own with a fixed prefix, so a provider's id never replaces an earlier step - verified by a graph test with a scripted model that returns two steps with the same id: both steps are stored, the first step's tool call and its result stay, the turn ends normally, `tools_used` counts both calls and the first step's source credit is still shown.
- [ ] Within one step, the grounding check and `human_review`'s edit branch still replace the message they mean to - verified by the existing tests passing and a test with a repeated id next to an edit and an answer that goes through the grounding check.
- [ ] The system prompt is unchanged - verified by the PR's diff (no change under `src/prompts/`).
**Notes:** found by security round 2 of PR #48 (T5.7), outside T5.7's criteria; the owner chose a ticket of its own on 2026-11-28. With the pinned `langchain-openai` 1.7.2 an AI message takes its id only from an `id` field inside the provider's message object (`_convert_dict_to_message`), which OpenAI's Chat Completions does not send; without it `langchain-core` gives each call a fresh `lc_run--<uuid>-<n>` id, so ids differ today. The risk is a provider behind OpenRouter that adds an `id` to the message and repeats it in two steps: `add_messages` would then replace the first step with the second (read in the code, not seen or checked against the live API). T5.7 already keeps ids that differ only by a lone surrogate apart (`clean_id`). Files: `src/agent/graph.py`, `src/safe_text.py` or `src/agent/runner.py`, tests; `security-reviewer` runs on the PR (it touches the graph). No new data flow.
