### T5.16 Approval panel design from the mockups (M) · status: todo · issue #44
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): interactive prototype, user interface and interaction quality, function calling (the human-in-the-loop step); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.3 (the parent sees what goes where), 2.11 (the memory save), 4.2 (no dark patterns), 3.4 (nothing from other hosts).
**Depends on:** T5.2 (the form and the three equal buttons), T5.12 (the design)
**Acceptance criteria** (drafted by Claude on 2026-11-26, approved by the owner on 2026-11-27)
- [ ] While the agent waits, the panel opens with a yellow box "1 step is waiting for you" or "N steps are waiting for you" - verified by an `AppTest` with one and with two pending calls.
- [ ] Each pending call is one bordered card with "Step n of m", a plain title from `PROGRESS_TOOL_LABELS`, the explanation, T5.2's fields and the tool name as small plain text - verified by an `AppTest` per tool kind (a form tool, the budget table, a memory save, a tool without a form).
- [ ] Each card has a data-flow badge chosen by the app from a fixed table in `src/config.py` (one entry per tool, the memory save included), never by the model (owner decisions of 2026-11-27): a step that contacts a map, event, weather, geocoding or train service (today `find_nearby_places`, `search_family_events`, `get_weather_forecast` and `find_train_connection`) gets a blue "Sends data to an outside service" with the name of every such service it contacts, as the captions do (e.g. the Open-Meteo geocoder and Overpass); a step whose only outside service is the AI model service (the knowledge base search, which sends its search text to the AI model service to find matches (the embedding always; the query rewrite and the rerank when switched on); the ticket comparison and the budget check, whose data or result the model reads at the next step) gets a violet "Only the AI model reads it" with the AI provider's name from `config.AI_PROVIDER_NAME` as its service name (today "OpenRouter (AI models)"); the memory save's entry is its own violet badge (next criterion); there is no green badge, because by the registers no step stays fully inside the app - verified by a test that checks the table against the tool registry (an entry for every tool) and checks that exactly those four tools have the blue badge, and by a hand check of the table against the registers in `docs/LEGAL_COMPLIANCE.md` in the PR's Legal check.
- [ ] A memory save (`remember_preference`) never gets the blue badge or "Only the AI model reads it": while memory is on it gets a violet "Sent to the AI model with later questions" badge next to the app's own "🧠 Save to memory: …" text; while it is off the step keeps "(Memory is off: it will not be saved)" and no badge - verified by `AppTest`s with memory on and off.
- [ ] Under the budget table (a badge cannot sit inside `st.data_editor`), each unknown cost is one line: a yellow badge holding only the fixed word "unknown", then its label (written by the model) shown with `st.text`, never in the same Markdown as the badge, so nothing in it can load from another host (3.4) - verified by an `AppTest` with the labels `[x](https://evil.example)` and `![x](https://evil.example/x.png)` that appear literally.
- [ ] While the panel waits, the disabled chat box says "Answer the steps above first: approve, change or reject" - verified by an `AppTest`.
- [ ] An unknown or look-alike tool name (e.g. `remember_preference` with a zero-width space) gets a generic title, the blue badge naming "an unknown service" and never "Only the AI model reads it", the memory-save badge or the memory-save sentence; the tool name is shown with `st.text` (never `st.caption` or `st.markdown`, which render links and images), and badges and `:color[...]` hold only the app's fixed text - verified by `AppTest`s with such a name and with a name holding a Markdown link and image.
- [ ] The app's own texts match the badges (owner decision 2026-11-27): the captions of the knowledge base search, the ticket comparison and the budget check no longer say "Nothing leaves the app" or "inside the app" but say what the AI model service reads (and that no map, event, weather or train service is contacted), and the budget and ticket captions keep that the app, not the AI model, does the arithmetic (4.3); the `README.md` tool table no longer says the knowledge base search "stays inside the app"; the About page's human-in-the-loop line says the parent approves before any call to a map, event, weather or train service unless they switch on auto-approve in the testing settings, while the knowledge base search's calls to the AI model service run without a pause - verified by a test that joins each `TOOL_EXPLANATIONS` value (a caption can be split across string pieces) and finds neither phrase, a text search of `README.md`, and an `AppTest` of the About page line.
- [ ] T5.2's protections stay: the Approve lock while a field differs, only Reject with repeated call ids, widget keys tied to the pause, the memory save cut to topic and feeling - verified by T5.2's tests passing unchanged.
- [ ] Badges and boxes use only Streamlit's own elements (`st.badge`, `:color[...]`, `st.warning`, `st.container(border=True)`): no CSS, no `unsafe_allow_html`, no new `st.html`, nothing loaded from another host, and the three buttons keep the same type - verified by a test that searches `views/` and by T5.2's button test.
