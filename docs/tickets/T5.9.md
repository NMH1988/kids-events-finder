### T5.9 Faster answers: under 30 seconds on average (M) · status: todo · issue #33
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): evaluation (responsiveness: the SMART goal's average answer under 30 seconds); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.10 (logs hold event names and error types only), registers (Overpass: light use only); `docs/THIRD_PARTY_TERMS.md` (limits, stop on HTTP 429).
**Depends on:** T1.8
**Acceptance criteria** (scope only; drafted by Claude, to be written in full after the first measurement and approved by the owner before the work on speed starts)
- [ ] The `tool_http_error` log line names the tool and the HTTP status code (or the error type when there is none), never the URL, its parameters or a key - verified by a log test with a mocked request.
- [ ] `scripts/evaluate_agent.py` prints, per answer, the time spent in model calls and in each tool (numbers and tool names only) - verified by a unit test with fake models and tools.
- [ ] A calling tool stops on HTTP 429 and the agent goes on without it; the evaluation spaces out its calls to the public Overpass server - verified by tests with mocked responses.
- [ ] The average answer time with `openai/gpt-5-mini` is under 30 seconds on the 34 evaluation questions, after changes chosen from the measurement (for example fewer tool rounds per answer, a limit on rounds, or a faster model for the helper steps) - verified by a `--judge` re-run after the owner's go-ahead, recorded in `docs/EVALUATION.md` with the grounded and relevant-named rates, which must not fall.
**Notes:** follow-up from T1.8: 44.4 s (gpt-5-mini) and 57.2 s (gpt-5-nano) against the 30 s target; answers with more tool rounds took up to 124 s; 16 and 9 `tool_http_error` lines whose tool and cause the log does not show. A change to the system prompt (for example to ask for fewer tool rounds) needs the owner's approval. Re-runs are paid calls on the school's OpenRouter account and follow the checklist in `docs/THIRD_PARTY_TERMS.md`.
