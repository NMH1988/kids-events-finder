### T5.9 Faster answers: under 30 seconds on average (M) · status: todo · issue #33
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): evaluation (responsiveness: the SMART goal's average answer under 30 seconds); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.10 (what logs may hold), 6.4 (models only under checked terms), registers (Overpass: light use only); `docs/THIRD_PARTY_TERMS.md` (Overpass limits, the checklist before a re-run).
**Depends on:** T1.8
**Acceptance criteria** (drafted by Claude, to be approved by the owner; criterion 4's changes are chosen after criterion 2's measurement and approved by the owner before they are made)
- [ ] The `tool_http_error` log line, as printed, names the tool and the HTTP status code (or the error type when there is none), never the URL, its parameters or a key; `docs/LEGAL_COMPLIANCE.md` 2.10 and `CLAUDE.md` ("event names and error types only") are widened to allow the tool name and status code in the same PR - verified by a log test with a mocked request and the diff.
- [ ] `scripts/evaluate_agent.py` prints, per answer, the time spent in model calls and in each tool (numbers and tool names only, no tracing service) - verified by a unit test with fake models and tools.
- [ ] After an HTTP 429 or 406 from Overpass, the app makes no further Overpass call for at least 30 seconds (a constant in `src/config.py`) and the agent goes on without it; the evaluation waits a set time between questions that call Overpass - verified by tests with mocked responses and a fake clock.
- [ ] The average answer time with `openai/gpt-5-mini` is under 30 seconds on the 34 evaluation questions, after the changes chosen from the measurement (for example fewer tool rounds per answer, a limit on rounds, or a faster model for the helper steps) - verified by a `--judge` re-run after the owner's go-ahead, recorded in `docs/EVALUATION.md` with the grounded and relevant-named rates, which must not fall.
**Notes:** follow-up from T1.8: 44.4 s (gpt-5-mini) and 57.2 s (gpt-5-nano) against the 30 s target; answers with more tool rounds took up to 124 s; 16 and 9 `tool_http_error` lines whose tool and cause the printed log does not show (the record carries the tool name in `extra`, the default format drops it). A change to the system prompt needs the owner's approval. A faster or other model must be in `config.ALLOWED_MODELS`, with its row in the processor register and its entry in `docs/THIRD_PARTY_TERMS.md` updated in the same PR (6.4). Any cache holds only service results, never the question, the age groups or the trip settings, and respects each service's caching terms (Ticketmaster). Before a re-run the owner reads the Overpass usage terms by hand (a wiki page). Re-runs are paid calls on the school's OpenRouter account and follow the checklist in `docs/THIRD_PARTY_TERMS.md`. Runs since T5.11 offer the agent the `remember_preference` tool and a memory section in the system prompt, which the 2026-11-24 baseline did not have, so its figures are not directly comparable; the re-run keeps long-term memory off (the script's default), so no remembered preference reaches OpenRouter and the memory store is neither read nor written.
