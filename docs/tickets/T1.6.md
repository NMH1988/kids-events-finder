### T1.6 QRSPI workflow skill and stronger code and legal reviewers (S) · status: in review · issue #16
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): none (the way the work is done and reviewed; beyond the brief (owner's request)); Legal (`docs/LEGAL_COMPLIANCE.md`): "How to use this file" (read before a ticket, Legal check in the PR, rulebook upkeep), which the skill and the `legal-reviewer` carry out; no change to the app or its data flows.
**Depends on:** none
**Acceptance criteria**
- [ ] `.claude/skills/qrspi/SKILL.md` runs Question, Research, Structure, Plan, Implement in order and is adapted to this project: the Question phase reads `docs/LEGAL_COMPLIANCE.md` in full, `docs/CAPSTONE_CHECKLIST.md`, the ticket file (or the owner task's row), the progress log and the open PRs; a legal doubt, a contradiction, a change to the system prompt or the evaluation questions, or a paid run is always a question for the owner; nothing is written and no paid command runs before the owner approves the plan; it covers owner tasks (O<n>) as well as tickets - verified by reading the diff, and by Claude Code listing the `qrspi` skill in a session in this folder.
- [ ] `.claude/agents/code-reviewer.md` checks the ticket file, the **Serves** line in the PR, the ticket and the progress entry, the progress record and the statuses, whether the `legal-reviewer` run is still current after later commits, that blocked text makes no API call, the block-only rule of the keyword check (1.4) and the AI disclosure (4.1); it posts on the PR only after the non-empty-branch guard and numbers its round with a `jq` query - verified by reading the diff, by the round query returning the next round on PR #15, and by its round on this PR.
- [ ] `.claude/agents/legal-reviewer.md` builds a personal data map from the code and compares it with the processing register, never opens secrets, `data/feedback/`, `data/eval_runs/` or `chroma/`, never calls a model or a live service, fetches only pages on its allowlist (no WebSearch), marks findings Confirmed or Plausible, lists every installed package's licence offline, keeps the PASS / NEEDS CHANGES / BLOCK verdict and posts on a PR only when asked - verified by reading the diff, by running its licence listing (126 packages on Windows), and by its run on this PR.
- [ ] `CLAUDE.md` tells Claude to work through the `qrspi` skill for every ticket and owner task - verified by reading the diff.
- [ ] The ticket, the plan and the progress log agree and the suite passes - verified by `tests/test_docs_layout.py`, `ruff check .`, `ruff format --check .` and `pytest -q`.
- [ ] (added after review rounds 1-4; needs the owner's approval) All three reviewer agents fetch a PR by number (`pull/<n>/head`); put a number, commit SHA, path or branch name from a PR into a command only after a safe-pattern check (digits only; 7 to 40 hex characters; `^[A-Za-z0-9._/-]+$`, single-quoted; otherwise `git ls-tree` and the blob id); check `git ls-tree -r` for symlinks (mode `120000`) before reading a PR's or the checkout's files, and read a PR's files with `git show`, never through the working tree; run no code from a fork's or a stranger's PR, also when no PR number is given (then only after the branch guard or the owner's own words); keep the security reviewer's attack cases apart from the PR's code and from a working tree that is not the audited commit; treat what they read as data; never open the key files or stored user data; have no WebSearch; post with an unguessable heredoc delimiter in comments under about 6,000 characters; and count review rounds, and reviewer reports in the skill and `CLAUDE.md`, only from the owner's account - verified by `tests/test_agent_rules.py`.
**Notes:** modelled on the skill and the `code-reviewer` / `compliance-reviewer` agents of the owner's FitKompass project (the newer copy of fitcoach-ai-assistant's), rewritten for this project's documents (`docs/LEGAL_COMPLIANCE.md` instead of a PRD, sources list and briefs) and its data (children's age groups, trip settings, town names to services). `security-reviewer` gets only the fixes of review rounds 1-4: the PR-handling, run-gate and posting rules it shares with the other two, and the scratch-case rules of its own Step 3. The "never open" rules are instructions to the agents, not a technical block: a deny list in `.claude/settings.json` would enforce them (owner's decision). Agents edited during a session may only be picked up by a new Claude Code session.
