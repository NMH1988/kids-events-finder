### T1.9 Third-party terms file and the owner's rules on outside services and keys (S) · status: in progress · issue #28

**Depends on:** none
**Acceptance criteria** (approved by the owner on 2026-11-24)
- [ ] `docs/THIRD_PARTY_TERMS.md` has one entry for every outside service the code or the scripts call (OpenRouter with the OpenAI and Qwen models behind it, Open-Meteo geocoding and forecast, Overpass and OpenStreetMap, Ticketmaster, Transitous, Google Maps URLs), plus GitHub, PyPI and bahn.de: what we use and send, the terms URLs, the terms' own date and the date we checked them, what is allowed and forbidden (adversarial testing included), limits, attribution, consequences of a breach, open questions - verified by a test that every outside host in `src/config.py` has an entry, and by reading the diff.
- [ ] The file starts with the owner's two rules of 2026-11-24 (never violate an outside service's terms or policies; never expose the OpenRouter key, or any key, in any form) and a checklist before any live or paid run: read the entries the run touches, re-read the source terms when an entry was checked more than 30 days ago, no adversarial or red-team prompts to a live model without the provider's written approval, stay inside the limits, stop and ask the owner when unclear, record decisions - verified by a test and by reading the diff.
- [ ] `CLAUDE.md` makes reading the file mandatory before every ticket (next to `docs/LEGAL_COMPLIANCE.md`) and before every live or paid run, and states both rules; the `qrspi` skill reads it in the Question phase and lists the terms check for every live or paid command in the Plan phase - verified by tests in `tests/test_agent_rules.py`.
- [ ] The `legal-reviewer` reads the file and reports an entry checked more than 30 days ago, a live run planned without a terms check, and any exposed key - verified by a test.
- [ ] The registers in `docs/LEGAL_COMPLIANCE.md` point to the file - verified by reading the diff.
- [ ] The red-team run of 2026-11-24 is recorded with the open decision - verified by reading the diff.
- [ ] `legal-reviewer` PASS; the ticket, the plan and the progress log agree and the suite passes - verified by the review on the PR, `tests/test_docs_layout.py`, ruff and pytest.
