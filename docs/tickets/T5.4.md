### T5.4 Clear messages when the agent stops (S) · status: todo · issue #23
**Serves:** Capstone (`docs/CAPSTONE_CHECKLIST.md`): interactive prototype, user interface and interaction quality, multi-step reasoning and memory (the conversation survives a failed turn); Legal (`docs/LEGAL_COMPLIANCE.md`): 2.10 (logs hold event names and error types only).
**Depends on:** T5.1 (both change how a turn runs in `src/agent/runner.py` and `views/chat.py`)
**Acceptance criteria** (drafted by Claude, approved by the owner on 2026-11-24)
- [ ] When the agent reaches `AGENT_RECURSION_LIMIT`, the chat says that the question needed too many steps and suggests a narrower one, instead of "Something went wrong while calling the model service" - verified by a test with a fake model that keeps calling a tool.
- [ ] A model timeout or connection error says that the AI service did not answer in time and to try again; any other error keeps today's general message, and no message shows the error's own text - verified by tests with fakes that raise each error.
- [ ] After a turn stopped by the step limit or an error, the next question in the same conversation runs normally (no tool call left without its result in the thread) - verified by a graph test.
- [ ] The logs hold only the event name and the error type - verified by a `caplog` test.
**Notes:** files: `src/agent/runner.py` (catch `GraphRecursionError` and the client's timeout and connection errors, repair the thread if it ends with unanswered tool calls), `views/chat.py` (`_run`). The exact exception classes come from `langgraph` and the OpenAI client behind `src/llm.py`; checked in Research.
